# Terraform Multipass Infrastructure for Nomad + Consul (local Mac testing)

This directory provisions the same server/client cluster topology as
[../aws/](../aws/), but on local [Multipass](https://multipass.run/) VMs
instead of AWS EC2 instances. It exists for testing on an Apple Silicon
(or Intel) Mac without an AWS account, using the existing Ansible
roles/playbooks in [../../ansible/](../../ansible/) almost unmodified.

Refer to [../../_context/wiki/multipass-local-testing-plan.md](../../_context/wiki/multipass-local-testing-plan.md)
for the full design rationale.

## Prerequisites

```bash
brew install --cask multipass
multipass version
```

An existing local SSH key pair (default: `~/.ssh/id_ed25519` /
`~/.ssh/id_ed25519.pub`). No new keypair is generated by Terraform here —
unlike [../aws/keypair.tf](../aws/keypair.tf), Multipass has no first-class
key-pair object, so your existing key is injected via cloud-init instead.

## What gets created

| Resource | Count | Details |
|----------|-------|---------|
| `local_file` (cloudinit) | 1 | Rendered cloud-init user-data appending your SSH public key to the `ubuntu` user |
| `multipass_instance` (servers) | 3 (default) | Ubuntu 24.04, 2 CPUs, 4GB RAM, 10GB disk |
| `multipass_instance` (clients) | 2 (default) | Ubuntu 24.04, 2 CPUs, 4GB RAM, 10GB disk |
| `local_file` (inventory) | 1 | `../../ansible/inventory.ini` (same path [../aws/](../aws/) writes to) |

No AMI, security group, IAM role, VPC, or subnet resources — Multipass has
no equivalent objects. VMs are reachable directly from the host over
Multipass's own virtual network.

**Run AWS or Multipass, never both at the same time.** Both workspaces
generate `ansible/inventory.ini`, so applying one overwrites the other's
inventory (and, once you deploy, `ansible/tokens/` and `ansible/.tls/`
describe whichever cluster you deployed most recently). Switching back to
AWS is just `terraform apply` again in [../aws/](../aws/). Sharing one path
is intentional: every playbook, including `teardown.yaml`, works unmodified
against either environment with `-i inventory.ini`.

## Usage

```bash
cd terraform/multipass
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars if your SSH key lives somewhere other than
# ~/.ssh/id_ed25519[.pub]

terraform init
terraform plan
terraform apply

# confirm VMs are up
multipass list

# deploy the cluster (from ansible/), e.g. Scenario C:
cd ../../ansible
ansible-galaxy install -r requirements.yaml
ansible-playbook -i inventory.ini deploy_consul_nomad_sd.yaml
```

## Teardown

```bash
cd terraform/multipass
terraform destroy
```

If VMs are left behind or Terraform state drifts, use Multipass directly as
an escape hatch:

```bash
multipass delete --all --purge
```
