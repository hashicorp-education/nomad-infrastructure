# Ansible configuration for Nomad cluster

This directory contains Ansible playbooks and roles to install and configure a co-located HashiCorp Nomad v2.0.4 + Consul v2.0.1 cluster on the infrastructure provisioned by Terraform.

**[Complete deployment guide](../DEPLOY_CLUSTER_GUIDE.MD)** — Step-by-step instructions for the full deployment process.

## Overview

The Ansible configuration automates the complete setup of the cluster, including:

- Base system configuration and package installation
- TLS certificate generation and distribution
- Container networking setup (CNI plugins)
- Docker installation on client nodes
- Consul and Nomad binary installation and configuration
- Systemd service management
- AWS Cloud Auto-Join for Consul
- ACL bootstrap for both Consul and Nomad
- Consul-Nomad integration (service discovery and workload identity)
- dnsmasq `.global` DNS forwarding

## Quick start

After running `terraform apply`, the inventory file is automatically generated. Then run:

```bash
cd ansible

# Install required Ansible Galaxy roles and collections
ansible-galaxy install -r requirements.yaml

# Test connectivity
ansible all -m ping

# Deploy the full cluster (Consul + Nomad + service discovery + workload identity)
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml
```

**Expected duration**: ~10–15 minutes for a 5-node cluster (3 servers + 2 clients).

Refer to [PLAYBOOKS-README.md](PLAYBOOKS-README.md) for all available deployment scenarios.

## Playbooks

Use case entrypoints (run from the `ansible/` directory):

| Playbook | What it deploys |
|----------|----------------|
| `deploy_consul.yaml` | Consul servers + clients + ACL + DNS token + dnsmasq + anonymous-deny |
| `deploy_nomad.yaml` | Nomad servers + clients + ACL |
| `deploy_consul_nomad_sd.yaml` | Consul + Nomad + DNS token + service discovery |
| `deploy_consul_nomad_wi.yaml` | Consul + Nomad + DNS token + service discovery + workload identity |
| `teardown.yaml` | Removes everything Ansible installed |

Sub-playbooks in `playbooks/` can be run directly for targeted operations:

```bash
ansible-playbook -i inventory.ini playbooks/consul_servers.yaml
ansible-playbook -i inventory.ini playbooks/consul_acl_bootstrap.yaml
ansible-playbook -i inventory.ini playbooks/nomad_servers.yaml
ansible-playbook -i inventory.ini playbooks/nomad_acl_bootstrap.yaml
ansible-playbook -i inventory.ini playbooks/consul_nomad_service_discovery.yaml
ansible-playbook -i inventory.ini playbooks/consul_nomad_workload_identity.yaml
ansible-playbook -i inventory.ini playbooks/dnsmasq.yaml
```

Refer to [PLAYBOOKS-README.md](PLAYBOOKS-README.md) for detailed documentation on every playbook, its variables, output files, and run order.

## Roles

### common
**Purpose**: Base system configuration for all hosts

**Features**:
- Installs essential packages (jq, net-tools, ntp, unzip, curl, wget)
- Configures NTP for time synchronization
- Sets hostname based on inventory
- Updates system packages

**Used By**: Both server and client playbooks

**Documentation**: [`roles/common/README.md`](roles/common/README.md)

---

### cni
**Purpose**: Container Network Interface (CNI) plugins installation

**Features**:
- Downloads CNI plugins v1.9.1 from GitHub
- Installs to `/opt/cni/bin`
- Creates configuration directory at `/opt/cni/config`
- Only runs on Ubuntu systems

**Used By**: Client playbook only

**Why Needed**: Required for container networking in Nomad (bridge mode)

**Documentation**: [`roles/cni/README.md`](roles/cni/README.md)

---

### consul
**Purpose**: Consul agent installation and configuration

**Features**:
- Installs Consul 2.0.1 binary via `hashicorp_release` role
- Supports server mode and client mode (toggled by `consul_server_enabled`)
- Configures ACLs, TLS, gossip encryption, and Consul Connect (service mesh)
- Creates and validates systemd service

**Used By**: `consul_servers.yaml`, `consul_clients.yaml`, `consul_nomad_integration.yaml`

**Documentation**: [`roles/consul/README.md`](roles/consul/README.md)

---

### dnsmasq
**Purpose**: dnsmasq installation and Consul DNS forwarding

**Features**:
- Installs dnsmasq
- Disables systemd-resolved stub listener so dnsmasq can bind to port 53
- Forwards `.global` domain queries to the local Consul agent (port 8600)
- Binds to both `127.0.0.1` (host processes) and `172.17.0.1` (Docker task driver containers) so Nomad jobs using `dns { servers = ["172.17.0.1"] }` resolve `.global` names correctly
- Configures upstream DNS servers (AWS VPC resolver by default)
- Updates `/etc/resolv.conf`

**Used By**: `dnsmasq.yaml`

**Documentation**: [`roles/dnsmasq/README.md`](roles/dnsmasq/README.md)

---

### geerlingguy.docker (external role)
**Purpose**: Docker installation and configuration

**Features**:
- Installs Docker CE on client nodes
- Adds ansible user to docker group
- Configures Docker daemon
- Enables Docker service

**Used By**: Client playbook only

**Why Needed**: Required for running containerized workloads in Nomad

**Installation**:
```bash
ansible-galaxy install -r requirements.yaml
```

---

### hashicorp_release
**Purpose**: Generic role for installing HashiCorp products

**Features**:
- Downloads binaries from releases.hashicorp.com
- Verifies and handles version upgrades
- Supports multiple architectures (amd64, arm64, and others)
- Idempotent installation

**Used By**: Nomad role (indirectly)

**Supported products**: Nomad, Consul, Vault, Terraform, and Packer

**Documentation**: [`roles/hashicorp_release/README.md`](roles/hashicorp_release/README.md)

---

### helper
**Purpose**: Utility role for common operations

**Features**:
- Package installation (APT/YUM)
- File copy from local to remote
- Content writing to files
- Template processing
- Directory synchronization
- Systemd service management

**Used By**: Both server and client playbooks

**Why Needed**: Simplifies repetitive tasks and keeps playbooks clean

**Documentation**: [`roles/helper/README.md`](roles/helper/README.md)

---

### nomad
**Purpose**: Nomad agent installation and configuration

**Features**:
- Installs Nomad v2.0.4 via `hashicorp_release` role
- Creates configuration directories (`/etc/nomad.d`, `/opt/nomad/data`, `/opt/nomad/plugins`)
- Generates `nomad.hcl` from Jinja2 templates
- Sets up systemd service
- Supports both server and client modes (toggled by `nomad_server_enabled` / `nomad_client_enabled`)
- Handles ACL, TLS, telemetry, and cloud auto-join configuration
- Supports Consul integration via `consul {}` block when `nomad_consul_integration_enabled: true`

**Used By**: `nomad_servers.yaml`, `nomad_clients.yaml`, `consul_nomad_integration.yaml`

**Documentation**: [`roles/nomad/README.md`](roles/nomad/README.md)

---

### nomad_consul
**Purpose**: Configures Consul ACL resources for Nomad Workload Identity integration

**Features**:
- Creates Consul ACL policies for Nomad server and client agents
- Creates Consul ACL tokens for Nomad agent operations
- Creates Consul JWT auth method (`nomad-workloads`) pointing at Nomad's JWKS endpoint
- Creates Consul binding rules for service workload identities and task workload identities
- Creates Consul ACL role and policy for Nomad tasks
- Guarded by a sentinel file — runs exactly once per cluster

**Used By**: `consul_nomad_integration.yaml`

**Documentation**: [`roles/nomad_consul/README.md`](roles/nomad_consul/README.md)

---

### tls
**Purpose**: TLS certificate generation

**Features**:
- Generates self-signed Certificate Authority (CA)
- Creates individual certificates for each node
- Signs certificates with the CA
- Supports Subject Alternative Names (SANs)
- Stores certificates locally for distribution

**Used By**: Both server and client playbooks (in pre_tasks)

**Why Needed**: Enables secure communication between cluster members

**Documentation**: [`roles/tls/README.md`](roles/tls/README.md)

## Configuration variables

### Version variables

To pin Nomad, Consul, or CNI plugin versions, edit
[`ansible/group_vars/all.yaml`](group_vars/all.yaml). This file is the single
source of truth for product versions and takes precedence over the per-role
`defaults/` values.

### Nomad role variables

Located in [`roles/nomad/defaults/main.yaml`](roles/nomad/defaults/main.yaml):

```yaml
nomad_binary_version: "2.0.4"

nomad_server_enabled: false
nomad_server_bootstrap_expect: 3

nomad_client_enabled: false

nomad_cloud_auto_join_enabled: false
nomad_cloud_auto_join_tag_key: "AutoJoinRole"
nomad_cloud_auto_join_tag_value: "server"

nomad_acl_enabled: false
nomad_tls_enabled: true

nomad_log_level: "INFO"
nomad_log_file: "/var/log/nomad.log"

# Consul integration (set after running consul_nomad_integration.yaml)
nomad_consul_integration_enabled: false
nomad_consul_agent_token: ""
nomad_consul_address: "127.0.0.1:8500"
```

### Common variables

These can be overridden in playbooks or via command line:

| Variable | Default | Description |
|----------|---------|-------------|
| `nomad_binary_version` | `2.0.4` | Nomad version to install — set in [`group_vars/all.yaml`](group_vars/all.yaml) |
| `consul_binary_version` | `2.0.1` | Consul version to install — set in [`group_vars/all.yaml`](group_vars/all.yaml) |
| `cni_plugins_version` | `1.9.1` | CNI plugins version — set in [`group_vars/all.yaml`](group_vars/all.yaml) |
| `nomad_log_level` | `INFO` | Logging level (DEBUG, INFO, WARN, ERROR) |
| `nomad_acl_enabled` | `false` | Enable ACL system |
| `nomad_cloud_auto_join_enabled` | `true` | Enable AWS cloud auto-join |

## Usage examples

### Install required dependencies

Before running playbooks, install external roles and collections:

```bash
# Install Ansible collections
ansible-galaxy collection install community.crypto ansible.posix

# Install external roles
ansible-galaxy install -r requirements.yaml
```

### Configure entire cluster

Choose the use case entrypoint that matches your requirements:

```bash
ansible-playbook -i inventory.ini deploy_consul.yaml            # Consul only
ansible-playbook -i inventory.ini deploy_nomad.yaml            # Nomad only
ansible-playbook -i inventory.ini deploy_consul_nomad_sd.yaml  # Consul + Nomad + service discovery
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml  # Consul + Nomad + workload identity
```

### Configure only servers

```bash
ansible-playbook nomad_servers.yaml
```

### Configure only clients

```bash
ansible-playbook nomad_clients.yaml
```

### Check connectivity

```bash
ansible all -m ping
```

### Run ad-hoc commands

```bash
# Check Nomad version on all hosts
ansible all -a "nomad version"

# Check server members
ansible servers -a "nomad server members"

# Check node status
ansible clients -a "nomad node status"

# Restart Nomad service on servers
ansible servers -b -m systemd -a "name=nomad state=restarted"

# View Nomad logs
ansible all -b -a "journalctl -u nomad -n 50"
```

### Override variables

```bash
# Install a different Nomad version
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml -e "nomad_binary_version=2.0.4"

# Enable ACLs
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml -e "nomad_acl_enabled=true"

# Change log level
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml -e "nomad_log_level=DEBUG"

# Use specific inventory file
ansible-playbook -i custom_inventory.ini deploy_consul_nomad_wi.yaml
```

### Limit execution to specific hosts

```bash
# Configure only server-1
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml --limit server-1

# Configure only clients
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml --limit clients

# Configure specific hosts
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml --limit "server-1,client-1"
```

## Customization

### Modify server configuration

Edit [`nomad_servers.yaml`](nomad_servers.yaml) to change server-specific settings:
- Bootstrap expect count
- ACL settings
- Log levels
- Cloud auto-join parameters

Example:
```yaml
- role: nomad
  vars:
    nomad_server_enabled: true
    nomad_server_bootstrap_expect: 5  # Changed from 3
    nomad_acl_enabled: true            # Enable ACLs
    nomad_log_level: "DEBUG"           # More verbose logging
```

### Modify client configuration

Edit [`nomad_clients.yaml`](nomad_clients.yaml) to change client-specific settings:
- Server connection methods
- Network interfaces
- Resource limits
- Driver configurations

Example:
```yaml
- role: nomad
  vars:
    nomad_client_enabled: true
    nomad_log_level: "DEBUG"
    # Add custom client configuration
```

### Add custom tasks

Add custom tasks to the playbooks' `post_tasks` section:

```yaml
post_tasks:
  - name: Install monitoring agent
    ansible.builtin.package:
      name: prometheus-node-exporter
      state: present

  - name: Configure firewall
    ansible.builtin.ufw:
      rule: allow
      port: 9100
```

### Use different Nomad version

```bash
# Edit roles/nomad/defaults/main.yaml
nomad_binary_version: "2.0.4"

# Or override via command line
ansible-playbook -i inventory.ini deploy_consul_nomad_wi.yaml -e "nomad_binary_version=2.0.4"
```

```bash

ssh -i ssh_key.pem ubuntu@<server-ip>

# Check SSH key permissions
ls -la ssh_key.pem  # Should be 600

# Fix permissions if needed
chmod 600 ssh_key.pem
```

### Check Nomad service status

```bash
# Check service status on all hosts
ansible all -b -m systemd -a "name=nomad"

# Check if Nomad is running
ansible all -a "pgrep nomad"

# View service details
ansible all -b -a "systemctl status nomad"
```

### View Nomad logs

```bash
# View recent logs
ansible all -b -a "journalctl -u nomad -n 50"

# Follow logs in real-time
ansible all -b -a "journalctl -u nomad -f"

# View logs with timestamps
ansible all -b -a "journalctl -u nomad --since '10 minutes ago'"
```

### Verify cloud auto-join

```bash
# Check server members
ansible servers -a "nomad server members"

ansible all -a "nomad agent-info"

ansible all -b -a "journalctl -u nomad | grep 'auto-join'"
```

### Common issues

#### 1. "Permission denied" SSH error

**Problem**: Cannot connect via SSH

**Solution**:
```bash
chmod 600 ssh_key.pem
```

#### 2. "Module not found" error

**Problem**: Required Ansible collections not installed

**Solution**:
```bash
ansible-galaxy collection install community.crypto ansible.posix
```

#### 3. Docker not working

**Problem**: Docker driver not available in Nomad

**Solution**:
```bash
# Verify Docker is installed
ansible clients -a "docker ps"

# Check user is in docker group
ansible clients -a "groups ubuntu"

# Restart Nomad
ansible clients -b -m systemd -a "name=nomad state=restarted"
```

#### 4. CNI plugins missing

**Problem**: Bridge networking not working

**Solution**:
```bash
# Verify CNI plugins
ansible clients -a "ls -la /opt/cni/bin/"

# Check kernel module
ansible clients -a "lsmod | grep bridge"

# Verify sysctl settings
ansible clients -a "sysctl net.bridge.bridge-nf-call-iptables"
```

#### 5. Servers not forming cluster

**Problem**: Servers not discovering each other

**Solution**:
```bash
# Check IAM instance profile
# Verify AWS tags on instances
# Check security group allows internal traffic
# View Nomad logs for auto-join messages
ansible servers -b -a "journalctl -u nomad | grep 'auto-join'"
```

## Important notes

1. **IAM Instance Profile**: The Terraform configuration creates an IAM instance profile but doesn't attach it to instances. For cloud auto-join to work, you need to attach the instance profile to your EC2 instances in [`terraform/aws/compute.tf`](../terraform/aws/compute.tf).

2. **First Run**: The first playbook run will take several minutes as it downloads and installs Nomad, Docker, and other dependencies.

3. **Idempotency**: All playbooks are idempotent and can be run multiple times safely without causing issues.

4. **ACLs**: ACLs are disabled by default. Enable them in production by setting `nomad_acl_enabled: true` and running the bootstrap playbook.

5. **TLS**: TLS is enabled by default (`nomad_tls_enabled: true`, `consul_tls_enabled: true`). Self-signed certificates are generated by the `tls` role and distributed by the `helper` role automatically — no additional configuration is needed.

6. **Inventory File**: The inventory file is auto-generated by Terraform. Don't edit it manually as changes will be overwritten.

## Next steps

After running the playbooks:

1. **Verify cluster formation**:
   ```bash
   # SSH to a server
   ssh -i ssh_key.pem ubuntu@<server-ip>
   
   # Check server members
   nomad server members
   
   # Check client nodes
   nomad node status
   ```

2. **Access the Nomad UI**: Navigate to `https://<server-ip>:4646` (expect a self-signed certificate warning)

3. **Bootstrap ACLs** (if enabled):
   ```bash
   ansible-playbook nomad_acl_bootstrap.yaml
   ```

4. **Deploy your first job**:
   ```bash
   nomad job run example.nomad
   ```

5. **Set up monitoring**: Configure Prometheus to scrape metrics from `:4646/v1/metrics`
